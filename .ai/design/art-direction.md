# Art Direction — Engineering Editorial

## Character

Precise. Technical. Restrained. Confident.

The visual language combines:

- editorial portfolios;
- engineering drawings and architecture documents;
- industrial manuals and revision sheets;
- information-rich but calm interfaces;
- carefully typeset source-code annotations.

The site should communicate that its author designs systems deliberately.

## Core visual idea

Use **systems and flows** as the recurring theme:

`INPUT → PROCESS → STATE → EVENT → OUTPUT`

Express it through structure, relationships, annotation, rhythm, and diagrams—not warehouse clip art, literal boxes, or decorative circuit patterns.

## Visual grammar

Use consistently:

- project IDs: `P01`, `P02`, `L01`;
- section IDs: `01/`, `02/`, `03/`;
- revision markers: `REV.01`, `2026/09`;
- metadata labels: `ROLE`, `SYSTEM`, `FOCUS`, `STATUS`;
- fine rules, coordinate-like annotations, and grid references;
- controlled asymmetry across project compositions.

These elements must carry hierarchy or orientation. Do not scatter pseudo-technical labels randomly.

## Theme

Default to a warm, light, paper-like surface with graphite typography and one vermilion signal color.

Dark sections are permitted when they create meaningful contrast, not as a default “developer aesthetic.”

## Images and diagrams

- Prefer architecture diagrams, data flows, interface fragments, and restrained screenshots.
- Redact or reconstruct confidential interfaces rather than blurring them theatrically.
- Diagrams must be legible, semantically accurate, and accessible through nearby text.
- Never use meaningless AI-generated abstract technology imagery.

## Success test

On first view, the visitor should think:

> This engineer makes deliberate system decisions.

Not:

> This is another fashionable developer template.
